# 星载启动参数槽恢复审计（slot-audit）

星载控制器在切换启动参数槽时若突然断电，地面审查员可将从设备导出的扇区镜像提交到本应用，
后端按**物理写入顺序**逐字节重放，裁定重启实际会采用哪一代完整参数——写到一半的较新槽
**不会**被误报为可启动。每次审计以稳定标识提交，结论即刻冻结，可随时按标识复查。

## 扇区格式（定长 64 字节，小端）

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0  | 4  | 魔数 `SPSE` |
| 4  | 1  | 记录类型：1=槽页，2=准备记录，3=完成记录（只允许这三种） |
| 5  | 1  | 槽编号：0=A，1=B |
| 6  | 2  | 保留（必须为 0） |
| 8  | 4  | 事务标识 uint32 |
| 12 | 4  | 代次 uint32 |
| 16 | 4  | 载荷长度 uint32（0–32） |
| 20 | 32 | 载荷（零填充） |
| 52 | 4  | 载荷 CRC32 |
| 56 | 4  | 保留（必须为 0） |
| 60 | 4  | 扇区 CRC32（对 0–59 字节计算） |

准备记录与完成记录的载荷为 4 字节：其所属事务目标槽页载荷的 CRC32 摘要。

## 恢复裁定规则

- 仅当**同一事务**的准备记录 → 目标槽完整页 → 完成记录依次出现、全部完整、事务标识与
  载荷摘要相符时，才接受切换（提交一个恢复候选）。
- 以下情况均会**定位首个违约**并停止重放：截断（长度 ≠ 64）、校验和错误（扇区或载荷
  CRC32）、重复事务标识但内容不一致、完成记录指向未完成页、写入顺序错误、准备/页/完成
  之间摘要不符、非法 Base64。
- 裁决**不**使用最新页号、**不**忽略损坏记录、**不**只看完成标记。
- 结论保留最后一个有效代次的槽内容与摘要；首个违约之后的记录一律标记为“未评估”，
  不得覆盖已保留的有效代次。
- 多个提交代次相同，按物理槽名稳定选择（A 优先 于 B，再按提交先后）。
- 无完整提交事务时，保持初始活动槽。
- 页面与 API 都会展示每条记录被采纳或舍弃的依据。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET  | `/health` | 健康检查，返回 `{"status":"ok"}` |
| POST | `/api/audits` | 提交审计并冻结结论（重复标识返回 409） |
| GET  | `/api/audits/<id>` | 按标识查看已冻结结论 |
| GET  | `/api/example?scenario=complete\|corrupt-complete\|retain-old` | 生成示例扇区 |

提交体：

```json
{
  "audit_id": "audit-2026-001",
  "initial_slot": "A",
  "sectors": ["U1BTRQ==...", "... 至多 32 个 Base64 定长扇区 ..."]
}
```

## 本地运行

```bash
python3 -m app.server            # 监听 0.0.0.0:8000（HOST/PORT/DATA_DIR 可配）
python3 -m unittest discover -s tests -t .   # 运行单元测试
```

打开 `http://localhost:8000/` 使用页面；可一键载入三种示例场景。

## Docker / Compose

```bash
# 启动应用（宿主机端口可配置，默认 8080）
HOST_PORT=9090 docker compose up --build app
curl http://localhost:9090/health        # {"status":"ok"}

# 一键验证：构建检查 + 单元测试 + HTTP 冒烟（完整切换 / 完成标记损坏 / 旧有效槽保留）
# verify 服务运行一次后以退出码报告结果，以下命令的退出码即 verify 的退出码
docker compose up --build --exit-code-from verify
```

`verify` 服务等待 `app` 健康后执行：`compileall` 构建检查与模块导入、
`tests/` 单元测试、针对三个场景的 HTTP 冒烟（含冻结结论复查与重复提交 409 校验），
全部通过退出 0，否则退出 1。
